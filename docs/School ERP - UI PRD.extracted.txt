When the user's session has 5 minutes remaining, a banner appears at the top of every screen:
"Your session expires in 5 minutes. Click to extend." Clicking calls the refresh endpoint. If
session expires without extension, user is redirected to login; after logging back in, they are
returned to the page they were on.

B.2 Forgot Password
User journey:
1. On login screen, clicks "Forgot password?"
2. Enters their username → clicks "Send Reset Link"
3. Screen shows: "If this username exists, a reset link has been sent to the registered email."
4. User opens email → clicks reset link → lands on Reset Password screen
5. Enters new password + confirm password → clicks "Reset Password"
6. Success message shown → link to go back to Login
B.3 First Login — Forced Password Change
User journey:
1. First time a user logs in with a system-assigned password, they are automatically redirected
to the Change Password screen
2. They enter their current (temporary) password and a new password
3. After saving, they land on Dashboard
B.4 Change Password (from Settings)
User journey:
1. User is logged in, clicks their avatar → "Settings"
2. On Settings page, clicks "Security" tab
3. Enters current password, new password, confirm new password
4. Clicks "Update Password" → sees success message

PART Q — KEY UX RULES
These apply across all screens:
1. Destructive actions always require confirmation. Deactivate, Discontinue, Delete, and
Reject all open a confirmation modal before executing.
2. Blocked states are visible, not hidden. When a user doesn't have access to an action (e.g.,
Accountant cannot approve scholarships), the button is hidden. When a business rule blocks
an action (e.g., scholarship pending), the button is visible but disabled with a tooltip
explaining why.

3. Empty states are instructive. When a list is empty, show a message explaining why and
what action to take (e.g., "No fee structure configured. Click 'Configure' to set one up.").
4. Live calculation previews. Fee structure configuration and scholarship request forms show
live-calculated totals as the user types. No need to click a "Calculate" button.
5. Filters persist within a session. If a user filters the student list by "Class 8" and navigates
away and back, the filter is still applied.
6. Success feedback is always shown. Every save/create/update/delete shows a toast
notification confirming the action. Errors are shown inline near the relevant field or at the top
of the form.
7. Navigation is never blocked by unsaved changes without warning. If a user has unsaved
changes on a form and tries to navigate away, a browser-standard "You have unsaved
changes. Leave anyway?" prompt appears.
8. Paginated lists default to 20 items per page. All tables show "Showing X–Y of Z results"
text.
9. Dates are always displayed in DD-Mon-YYYY format (e.g., 28-May-2026). Date pickers
accept keyboard input and calendar selection.
10. Currency values are always shown with the ₹ symbol and formatted with Indian-style
comma grouping (1,24,600).
